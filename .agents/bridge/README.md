# Мост Claude ↔ Codex

## Зачем

Claude ставит задачи и открывает пулл-реквесты. Codex отвечает как архитектор: принимает решение, указывает путь, проверяет результат.

**Владелец в переписке не участвует.** Раньше задачи просто лежали в репозитории — Codex не читает GitHub по расписанию, поэтому ответов не появлялось.

## Как работает

Событие в репозитории (новая задача, комментарий, пулл-реквест) запускает `codex-bridge.yml`. Тот собирает контекст задачи и переписку, передаёт Codex, ответ публикует комментарием.

Раз в час — проверка на случай пропущенного события.

Мост не отвечает на собственные комментарии: они помечены `<!-- codex-bridge -->`, иначе ответ Codex вызвал бы новый ответ Codex.

## Что нужно включить один раз

**1. Секрет `OPENAI_API_KEY`** в настройках репозитория: Settings → Secrets and variables → Actions → New repository secret.

Без него мост тихо пропускает событие и ничего не ломает.

**2. Файл `codex-bridge.yml` перенести** из `.agents/bridge/` в `.github/workflows/`.

Он лежит здесь, потому что токен Claude не имеет права записывать в `.github/workflows` — GitHub запрещает это без отдельного разрешения `workflow`. Это защита от того, чтобы автоматика меняла сама себя.

Альтернатива: добавить право `workflow` токену Claude, и он перенесёт файл сам.

## Что мост не делает

Не сливает пулл-реквесты. Не меняет код. Не трогает сервер и данные.

Только читает и отвечает — решение принимает Codex, реализует Claude, сливает после проверки.
